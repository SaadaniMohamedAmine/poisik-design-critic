# 09 — Internationalization (i18n)

**Depends on:** `01-init-setup.md`, `06-support-pages.md`
**Goal:** the app fully works in French and English, including AI-generated content.

## Tasks

1. **Setup**
   - `next-intl` with locale-prefixed routing (`/en/...`, `/fr/...`)
   - Default locale: **English** (recommendation — this is a portfolio piece with an international audience; flag this choice to the project owner if French should be the default instead)

2. **String extraction**
   - `messages/en.json` and `messages/fr.json` covering every piece of static UI copy across all pages built in `06-support-pages.md` and `05-report-screen.md`
   - No hardcoded UI strings in components — everything goes through `next-intl`'s translation hooks

3. **Language switcher**
   - Small control in the top nav (e.g. "EN / FR" toggle), preserves the current route when switching locale

4. **AI report translation**
   - Preferred approach: pass the current `locale` into the system prompt built in `04-ai-analysis.md` and have the model generate `title`/`description`/`recommendation` directly in that language — cheaper and simpler than a separate translation pass
   - **Documented limitation:** a report already generated/shared in one language keeps that language even if the viewer later switches locale (do not attempt to re-translate stored reports)

5. **SEO**
   - `hreflang` alternate tags per page (from `08-assets-seo.md`'s metadata setup) pointing to the EN/FR equivalents

## Definition of Done
- Switching the language toggle updates every static string on the current page with no missing-translation fallbacks visible
- Running a new analysis while the FR locale is active produces a French-language report (titles, descriptions, recommendations)
- `hreflang` tags are present and correct in page `<head>`
